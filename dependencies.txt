ClamUI 0.6.0 — release dependency inventory
Date: 2026-11-11

Scope and version notation
--------------------------
This is an inventory, not an installation mechanism. The versions in the
Rust and desktop JavaScript lists below are exact versions resolved in the
release locks, not minimum system requirements. Cargo.toml and
desktop/package.json declare the corresponding requirements/ranges; consult
those files for their precise semantics. Cargo.lock and desktop/bun.lock are
the canonical, complete transitive dependency records. desktop/yarn.lock is a
Bun-generated export for the Flatpak offline build, not a separate version
selection. The website is a separate project with its own package.json and
bun.lock and is not part of the desktop application runtime.

Host runtime and optional integrations
--------------------------------------
- All application formats use host ClamAV: clamscan for scanning and
  freshclam for updating the host's virus definitions. Available, current
  signatures are needed for scanning. ClamUI does not ship the engine or
  its database. Flatpak invokes host tools via flatpak-spawn --host.
- Daemon scanning additionally needs host clamd, clamdscan and a reachable
  configured daemon. Scheduling uses a systemd user timer where available,
  otherwise cron. The network-socket audit uses host ss (iproute2).
- Applying protected host ClamAV settings requires the trusted host
  clamui-apply-preferences helper, its polkit policy and pkexec/Polkit
  authorization. The helper protocol is v4. Debian application and helper
  packages must match in version and architecture; the Fedora RPM is a helper
  package, not an application package.
- Secret Service on the session D-Bus provides the preferred desktop keyring
  for VirusTotal keys. Plaintext fallback requires explicit user consent.
  Notifications use the desktop notification service. The optional tray uses
  a StatusNotifierItem watcher; file-manager integrations require the
  corresponding Nautilus, Dolphin or Nemo environment.

Desktop and Flatpak runtime
---------------------------
- Native Linux desktop packages use GTK 3 and WebKitGTK 4.1 (including their
  system library dependencies). The Debian application control file names
  libgtk-3-0 and libwebkit2gtk-4.1-0; its package dependencies also include
  clamav, clamav-freshclam, pkexec or policykit-1, and the matching helper.
- The x86_64 AppImage bundles its GTK/WebKitGTK runtime; host ClamAV and
  optional host integrations remain separate.
- Flatpak app ID: io.github.linx_systems.ClamUI. Runtime: org.gnome.Platform
  51. Recipes target x86_64 and aarch64. The GNOME runtime supplies the
  sandbox desktop libraries, not the host ClamAV engine or definitions.
  Session D-Bus access is declared for Secret Service, notifications and
  StatusNotifier watchers; host integration uses org.freedesktop.Flatpak.

Build and release tooling (not end-user interpreter requirements)
------------------------------------------------------------------
- Rust stable and Cargo; native Debian/AppImage CI pins Bun 1.3.14. The
  workspace uses Rust edition 2021. CI uses locked Cargo dependencies and the
  desktop frontend lock; no exact Rust compiler version is pinned there.
- Native desktop builds need a C/C++ build toolchain, pkg-config and development
  files for GTK 3, WebKitGTK 4.1, JavaScriptCoreGTK 4.1, libsoup 3, librsvg,
  OpenSSL and libxdo. Debian packaging additionally uses gettext, dpkg-dev,
  fakeroot and dpkg-sig for signed packages. Release CI builds Debian on the
  Ubuntu 22.04-compatible amd64 and arm64 baseline.
- AppImage release CI builds x86_64 on Ubuntu 22.04, uses appimagetool 1.9.1,
  FUSE 2 and patchelf, and signs with GnuPG when requested. Helper RPM builds
  use the Rust core, GLib development files, pkg-config, rpm and GnuPG.
- Flatpak builds use org.gnome.Sdk 51, Flatpak Builder, and the
  org.freedesktop.Sdk.Extension.node24 and rust-stable extensions, both 26.08.
  The recipe uses Yarn 1 with the generated offline mirror and frozen export,
  plus Cargo offline with the locked generated sources. Bun is used to export
  the canonical desktop lock for Flatpak source generation; it is not an
  application runtime requirement.
